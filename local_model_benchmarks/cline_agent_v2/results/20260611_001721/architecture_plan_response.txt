### Implementation Plan for RelayBox with TaskAdvisor Integration

#### 1. **Hook Location**
The `consume_result(job_id)` method will be the primary hook location for integrating the `TaskAdvisor.analyze(description)` API. This method is responsible for consuming worker results and should remain synchronous to maintain the existing API contract.

#### 2. **Sync/Async Boundary**
- **Synchronous `consume_result`**: The `consume_result` method will remain synchronous to avoid changing the public API contract.
- **Asynchronous `TaskAdvisor.analyze`**: The `TaskAdvisor.analyze` method will be called asynchronously within the `consume_result` method to ensure that the added latency does not exceed two seconds.

#### 3. **Failure Behavior**
- **Timeout**: If `TaskAdvisor.analyze` takes longer than two seconds, it will be terminated, and the `consume_result` method will proceed without the advisory metadata.
- **Exception Handling**: Any exceptions raised by `TaskAdvisor.analyze` will be caught and logged, but the `consume_result` method will continue execution without the advisory metadata.
- **Unavailability**: If `TaskAdvisor.analyze` is unavailable, the `consume_result` method will proceed without the advisory metadata.

#### 4. **Telemetry**
- **Status**: Track the status of the `TaskAdvisor.analyze` call (success, timeout, exception, unavailability) and log it.
- **Latency**: Measure and log the latency of the `TaskAdvisor.analyze` call.

#### 5. **Tests**
- **Unit Tests**: Write unit tests for the `consume_result` method to ensure that it handles different scenarios (success, timeout, exception, unavailability) correctly.
- **Integration Tests**: Write integration tests to ensure that the `TaskAdvisor.analyze` call does not affect the checksum validation, consumption, or verdicts.

#### 6. **Rollback Mechanism**
- **No Rollback Needed**: Since the `TaskAdvisor.analyze` call is advisory-only and does not affect the core functionality of `consume_result`, there is no need for a rollback mechanism.
